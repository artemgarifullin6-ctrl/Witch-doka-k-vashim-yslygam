== Цель работы

Изучить среду разработки IAR Embedded Workbench for Arm, освоить процесс создания проекта для
микроконтроллера STM32F411RE, настройку стека и кучи, а также основы работы с языком C++ во
встроенных системах.

== Задание 1. Создание проекта и структуры

=== Ход выполнения

. Создан новый проект C++ по шаблону C++ — main.
. В проект подключён файл cstartup.cpp, переименованный в startup_stm32F411.cpp.
. Созданы папки:

AbstractHardware/Registers/FieldValues — описания полей регистров;

Common — общие определения;

Application — логика программы;

FreeRtos — заготовка для работы с ОСРВ.
. В среде IAR Workbench созданы соответствующие группы проекта: Abstract_Hardware, Application,
Common, FreeRtos.
. Настроены размеры сегментов STACK и HEAP (см. <<stack-heap-size>>).
. Скопировано содержимое папок Registers и Common из проекта преподавателя.

=== Программа в main.cpp

[source, cpp, linenums]

#include "gpiocregisters.hpp" //for GPIOC
#include "rccregisters.hpp" //for RCC
int main()
{
RCC::AHB1ENR::GPIOCEN::Enable::Set();
GPIOC::MODER::MODER5::Output::Set();
GPIOC::ODR::ODR5::Enable::Set();
GPIOC::ODR::ODR5::Disable::Set();
return 0;
}


=== Результат

Проект успешно собран, структура папок и групп в IAR Workbench соответствует требуемой.

== Задание 2. Компиляция, отладка и загрузка в плату

=== Ход выполнения

. Программа откомпилирована и отлинкована (Ctrl-F7).
. Выполнена загрузка в симулятор и пошаговая отладка (Ctrl-D).
. В настройках проекта выбран внутрисхемный отладчик ST-Link:

Options ⇒ Debugger ⇒ Driver ⇒ ST-Link.
. Плата подключена к компьютеру.
. Программа загружена в плату.
. Выполнена пошаговая отладка на реальном микроконтроллере.

=== Результат

При пошаговом выполнении программы наблюдается изменение состояния регистров RCC->AHB1ENR,
GPIOC->MODER, GPIOC->ODR. Светодиод, подключённый к выводу PC5, включается и выключается
в соответствии с логикой программы.

== Задание 3. Анализ стека, кучи и работа с Git

=== Анализ стека

Включена опция анализа стека:
Options ⇒ Linker ⇒ Advanced ⇒ Enable stack usage analysis.

После сборки в map-файле получена информация о максимальной цепочке вызовов. Например:

[source]

Call Graph Root Category Max Use Total Use

Program entry 896 896
Uncalled function 0 0

Рекомендуемый размер стека — 896 байт. В настройках проекта размер стека изменён на рекомендуемый.

=== Map-файл

Map-файл содержит:

карту распределения памяти (сегменты .text, .rodata, .data, .bss, CSTACK, HEAP);

адреса размещения функций и переменных;

информацию о перекрёстных ссылках;

результаты анализа глубины стека.

=== Установка размера кучи в 0

Куча HEAP установлена в 0 байт. Это допустимо, так как в программе не используется динамическое
выделение памяти (new/delete). Все объекты создаются статически.

Со стеком так поступить нельзя, поскольку стек используется:

для сохранения контекста при вызове функций;

для локальных переменных;

для сохранения регистров при входе в прерывания.

Даже простейшая программа использует стек для вызова main(), поэтому его размер не может быть
нулевым.

== Ответы на вопросы

=== Дайте определение понятию «интегрированная среда разработки»

Интегрированная среда разработки (IDE) — это программный комплекс, объединяющий в себе
текстовый редактор, компилятор, компоновщик, отладчик и другие инструменты, необходимые для
разработки программного обеспечения, в единый пользовательский интерфейс.

=== Что такое компилятор и чем он отличается от транслятора?

Транслятор — это общее название программы, преобразующей исходный код с одного языка
программирования в другой. Компилятор — это частный случай транслятора, который преобразует
исходный код языка высокого уровня в объектный код или машинный код. Таким образом, компилятор
является одним из видов транслятора.

=== Что такое компоновщик и какие функции он выполняет?

Компоновщик (линковщик) — это программа, которая объединяет объектные файлы и библиотеки в
единый исполняемый файл. Он выполняет:

разрешение внешних ссылок между модулями;

распределение сегментов кода и данных по адресному пространству;

настройку адресов в соответствии с конфигурационным файлом линкера;

создание исполняемого образа программы (ELF, hex, bin).

=== Почему важен процесс проектирования ПО и какие задачи входят в этот процесс?

Проектирование важно, потому что позволяет:

снизить вероятность ошибок на ранних этапах;

обеспечить повторное использование кода;

упростить сопровождение и модификацию;

повысить надёжность и качество ПО.

В процесс проектирования входят:

анализ требований;

выбор архитектуры;

декомпозиция на модули;

определение интерфейсов;

выбор структур данных и алгоритмов.

=== Дорисуйте процесс разработки ПО с учётом итеративности связей

Процесс разработки ПО в IAR Workbench включает этапы: Design → Develop → Debug. С учётом
итеративности связи выглядят так:

Debug → Develop (исправление ошибок, доработка кода);

Debug → Design (пересмотр архитектуры при выявлении проблем);

Develop → Design (уточнение проектных решений в процессе реализации).

Таким образом, процесс является циклическим, а не линейным.

=== Зачем нужна отладка и в каких случаях она применяется? Для чего применяются точки останова?

Отладка нужна для поиска и устранения ошибок в программе. Она применяется:

при разработке нового кода;

при интеграции модулей;

при возникновении нештатного поведения;

при оптимизации производительности.

Точки останова (breakpoints) применяются для:

остановки выполнения программы в заданном месте;

анализа состояния переменных и регистров;

пошагового выполнения кода;

локализации места ошибки.

=== Какие ещё важные характеристики IAR Workbench можно добавить в таблицу?

Дополнительно можно добавить:

поддержка многозадачности и RTOS;

наличие статического и динамического анализа кода;

поддержка стандартов безопасности (IEC 61508, ISO 26262);

наличие встроенного симулятора;

поддержка отладчиков ST-Link, J-Link, CMSIS-DAP;

возможность генерации map-файлов и анализа стека;

поддержка C++17 и современных стандартов языка.
